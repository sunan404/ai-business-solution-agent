# 规则质量基线

版本：synthetic-development-v1；25 条样例，全部为作者构造的虚构文本。五类痛点的期望标签与“是否存在可识别目标”由作者手工标注，可查看 `data/evaluation_cases.json`。样例用于开发回归，不是独立留出集；作者同时维护规则和标注，存在设计偏差。

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate --check
```

脚本生成 `docs/evaluation-local.json`，保留每条期望/预测和失败，不选择性删除失败样例。CI 底线为痛点 F1 ≥0.80、整条匹配 ≥0.75 且无分析失败。

## 当前结果

| 指标 | 结果 | 定义 |
| --- | --- | --- |
| Pain precision | 93.3% | 微平均 TP/(TP+FP)，TP=14、FP=1 |
| Pain recall | 93.3% | 微平均 TP/(TP+FN)，FN=1 |
| Pain F1 | 93.3% | 上述 precision/recall 的调和平均 |
| 痛点整条匹配 | 92% | 25 条中 23 条标签集合完全匹配 |
| 目标存在性 | 96% | 是否抽取目标与标注是否存在一致；不评目标表述语义 |
| 原文摘录匹配 | 100% | 返回摘录是否是原文子串；不证明语义支撑充分 |

已知失败：E04 的客户交接被额外归到项目协作；E25 的“需求变更/验收退回”未命中现有协作关键词。E13 的目标与缺失指标在同一句时，缺失过滤会错过目标。保留这些错误作为后续回归任务。

普通原句可同时表达目标、角色与客户关注点，重复引用不应被当作重复独立证据。这个基线未衡量方案可执行性、建议质量、优先级是否合理、行业覆盖或隐私风险。

## LLM 基线状态

**未执行真实 LLM 质量评估，也没有 LLM 准确率。** 模型输出痛点标题是开放式的，不能直接与本地五类标题做字符串准确率比较。当前脚本对 `--mode llm` 明确拒绝运行，防止产生误导分数或意外费用。

下一步应独立建立更多完整访谈的留出集，由业务评审者按类别、证据充分性、未知信息处理和建议质量标注；记录模型版本与人工评分。真实调用需额外确认费用、样例权限与可用预算，不能用模拟请求代替质量基线。

## 真实 API 联调校准（2026-09-30）

使用 DeepSeek `deepseek-flash` 和两个仓库虚构案例；输出上限 6,000、超时 60 秒、重试 0。修正前 5 次调用返回了内容但未通过字段/等级校验，均被拒绝；补充完整痛点格式示例和等级枚举后，游戏与品牌各 1 次通过 JSON、字段、等级与证据校验。全部 7 次记录（2 成功、5 失败）保留在 [llm-calibration.json](llm-calibration.json)，不隐藏失败。

| 最新通过案例 | 输入字符 | 输入 tokens | 输出 tokens | 端到端秒 | 估算 USD |
| --- | --- | --- | --- | --- | --- |
| 游戏发行 | 1,496 | 1,958 | 2,053 | 12.046 | 0.003051 |
| 消费品牌 | 2,016 | 2,257 | 1,457 | 9.597 | 0.0024255 |

这两份样例输出未达到 6,000 上限，不能证明长文档一定够用，更没有测试 60,000 字符的真实请求。采用输入 $0.3/百万、输出 $1.2/百万的配置费率估算，不扣除缓存或非高峰折扣，最终以账户账单为准；7 次估算合计约 $0.02159。修正后的 2/2 仅是小样本联调通过，不是可靠性或准确率基线。证据子串校验不证明业务判断正确，仍须人工审阅。
