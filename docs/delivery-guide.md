# 试点交付与案例演示指南

本版本用于单机作品集演示和人工辅助诊断。它是调用现有模型的应用，没有训练或交付自有基础模型。所有案例与以下试点设计均为虚构方案，未经客户确认，不代表实施成果。

## 游戏发行：从素材延期到四周试点

输入 `data/demo_game_publisher.md`。先核对 G01 的交付时间与 G02 的数据口径；排序可能受规则影响，不把生成顺序当作业务最终决策。

讨论建议：市场负责人建立素材任务台账，设计与本地化更新状态；每项任务保留负责人、依赖项、截止时间和批准版本。第一周走查流程并记录基线，第二周配置台账和权限，第三周试运行，第四周复盘。范围仅限泰国素材项目，广告平台保持现状。

验收参考：抽查任务是否具备必填字段；抽查外部伙伴是否只能看到批准素材；比较记录中的准时交付率与基线。改善幅度和目标值必须经客户确认。追问预算、审批权、准确基线，不推断收入收益。

## 消费品牌：从排期不同步到渠道台账

页面选择消费品牌案例，将访谈与 Excel 一起分析。也可分别上传，以演示不同证据产生不同诊断。

讨论建议：销售维护渠道主档与下一步动作，市场维护统一活动排期，运营建立发货量与终端销量数据字典，财务确认审批边界。先在六个演示渠道试点，第一周核对字段与权限，第二周导入脱敏样本，第三周运行一次活动，第四周复盘交接完整性与汇总耗时。

验收参考：抽查档案是否有维护人和更新时间；确认重复通知记录可追踪；核对看板不混加发货量与终端销售量。目标值和完整历史数据尚缺，不输出已提高效率的结论。

## 交付演示检查

1. 无密钥启动，两个案例均能生成带证据的本地报告并下载。
2. 粘贴“需要改善业务”，检查缺失信息以问题呈现。
3. 本机配置 `.env`，重启后选择 LLM；用虚构资料进行一次人工核验。
4. 校验 JSON、等级和证据；失败时显示明确提示，手动切换本地模式。
5. 下载后操作页面，原报告仍保留；改变输入或模式时不再显示旧报告。

已提供共享口令访问门、会话/全局/服务端客户配额，以及从环境读取密钥的部署配置；这些不是企业身份系统或托管秘密管理服务。公开上线仍需 HTTPS、服务端登录限流、细粒度权限和运营方的秘密管理设施。
